# 通用前端操作技巧

> 从实战里抽出来的可复用技巧。全部是浏览器里通用的 DOM 操作，跟具体哪个网站无关，
> 换任何 SPA / 富文本 / 受控表单场景都能用。配合任意浏览器自动化环境或手动 DevTools 都成立。

---

## 一、富文本编辑器（TinyMCE）

博客正文、建议正文这类富文本，内容在 iframe 里，不在当前 document。

```js
const f = document.querySelector("iframe.tox-edit-area__iframe");
const doc = f.contentDocument;
doc.body.focus();
doc.body.innerHTML = html;
doc.body.dispatchEvent(new Event("input", { bubbles: true }));
```

**多个编辑器时取最后一个**：

```js
const f = Array.from(document.querySelectorAll("iframe.tox-edit-area__iframe")).pop();
```

**粘贴长文本**：先 focus body 并清空，再用键盘粘贴（比直接写 innerHTML 更接近真实输入，能触发编辑器自己的字数校验）。

## 二、受控组件填不进值 → 原生 setter

Vue / React 的受控输入对直接赋 `.value` 不认，因为框架用自己的状态覆盖了。
要用原型链上的原生 setter，再派发 input / change 事件：

```js
const setter = Object.getOwnPropertyDescriptor(
  window.HTMLTextAreaElement.prototype, "value"
).set;
setter.call(el, text);
el.dispatchEvent(new Event("input",  { bubbles: true }));
el.dispatchEvent(new Event("change", { bubbles: true }));
```

`HTMLInputElement.prototype` / `HTMLTextAreaElement.prototype` 按元素类型选。

## 三、选择器命中隐藏元素 → 可见性筛选

**现象**：`fill` 报成功，页面却没内容。

**原因**：同一个 class 常有多个元素（PC 版 + 移动版），选到了 `display:none` 的那个。

**解法**：唯一属性 + 判断可见。

```js
const el = Array.from(document.querySelectorAll("textarea"))
  .find(t => t.placeholder?.includes("写下您的评论")
          && t.getBoundingClientRect().width > 0);
```

## 四、点击没反应

按这个顺序试，多数「点了没用」都落在前三条：

1. **点元素本身**，别点外层容器。有些按钮的事件绑在特定子元素上，点外层不触发。
2. **`element.click()`（JS 原生）**。实测某些 Star 按钮：坐标点击、强制点击、完整事件链派发**全部不发请求**，只有原生 `.click()` 管用。
3. **强制点击** `{ force: true }`：元素被遮挡或命中判定失败时。
4. **调页面自己的函数**：某些提交按钮点了没反应，直接调 `window.submitForm()` 之类的页面函数更稳。
5. **表单直接提交**：所有点击方式都无效时（如 OAuth 授权页），补隐藏字段后 `form.submit()`：
   ```js
   const form = document.querySelector("form");
   const inp = document.createElement("input");
   inp.type = "hidden"; inp.name = "authorize"; inp.value = "1";
   form.appendChild(inp);   // 常需补这个字段，否则返回 400
   form.submit();
   ```

**点之前先读状态**：如 Star 按钮，先读文本是 `Star` 还是 `Starred`，`Starred` 再点会取消。

## 五、元素在视口外 → 滚动后重取坐标

`element is not visible in the viewport` 超时。

```js
el.scrollIntoView({ block: "center" });
// 等渲染稳定后重新取 rect，滚动会让旧坐标失效
```

**每次操作前重新取 `getBoundingClientRect()`**，别复用滚动前的坐标。

## 六、SPA 页面抓不到内容 → 等渲染完

- 首次加载常只渲染导航，主体要靠后续请求或滚动触发懒加载
- 等 9 秒比 5~6 秒稳
- 必要时 `reload()` 一次或滚动到主体区域
- 判断「渲染完了」看主体 DOM 节点出现，别只等固定时间

---

## 七、iframe / 跨域

- 同源 iframe：`iframe.contentDocument` 可以直接读写
- 跨域 iframe：拿不到 contentDocument，**把它的地址单独开一个标签**操作更稳
- 后台标签页可能不计时（如「浏览案例」要停留满 40 秒），先 `bringToFront` 置前台

---

## 八、读图与 canvas 导出

远程桌面 / 图像内容在 canvas 里时，同源且未被跨域图片污染，可直接导出像素：

```js
const c = [...document.querySelectorAll("canvas")]
  .sort((a, b) => b.width * b.height - a.width * a.height)[0];
const dataUrl = c.toDataURL("image/png");
// 再 Buffer.from(base64) 写成文件
```

实测 245KB 的 dataURL → 184KB PNG。跨域图片画进 canvas 会让 `toDataURL` 抛安全错误，那时只能截图。

## 九、命令行环境（Windows）

- **CLI 版本按运行中的浏览器 `ProductVersion` 取**，别按安装目录的最大版本号——目录里常留多个版本
- Windows 上 `lark-cli` 是 `.cmd`，Python `subprocess` 调 `.ps1` 会 FileNotFound
- PowerShell 5.1 传含双引号/多行的 `-e "..."` 会丢引号 → 写成 `.mjs` 文件用 `import()` 调
- **JSON / 命令行参数里别出现尖括号 `< >`**：cmd 会当重定向符号，报「系统找不到指定的文件」
- 中文脚本用 UTF-8 写，`Set-Content` 默认编码会乱码

---

## 十、操作节奏

- 两次操作之间留间隔（建议 ≥1 秒），**节奏太规整会明显不像人在操作**
- 需要「停留计时」的任务，确保页面在前台、窗口没最小化
- 别反复刷新同一页面看状态，状态是后台结算的，刷新不会让它更快
