# 实战难题与解法

> 按「现象 → 原因 → 解法」写。收录浏览器环境、登录态、前端操作、任务判定四类坑。
> 所有前端技巧都是通用 DOM 知识，换任何站点都能用。

## 一、浏览器与环境

### 1.1 命令行工具报 `Failed to connect to bootstrap`

**现象**：浏览器自动化 CLI 一条命令都跑不了，还附带一句「cannot connect from the default agent sandbox」。

**真因**：**CLI 版本和正在运行的浏览器版本不一致**，不是沙箱问题。那句 sandbox 提示会把人带偏。

**解法**：按浏览器可执行文件的 `ProductVersion` 取 CLI，不要按「最大版本号」取。安装目录里常留多个版本（见过两个版本并存），按最大号取必错。

```powershell
$ver = (Get-Item '<浏览器安装目录>/<启动器>.exe').VersionInfo.ProductVersion
$cli = "<浏览器安装目录>/$ver/<命令行工具>.exe"
```

**交叉验证**：命名管道名里的版本号应该和它一致。

### 1.2 浏览器是不是活着，别看端口

它可能**不监听任何 TCP 端口**（9222/9223 永远关着但完全正常）。判据是进程数和它自己的任务空间是否还在。

### 1.3 截图报 `Cannot capture a screenshot while the window is minimized`

窗口最小化了。先还原窗口再截。

### 1.4 PowerShell 把脚本里的引号吃掉

用 `node -e "..."` 传多行脚本或含双引号的脚本，Windows PowerShell 5.1 会丢引号、把脚本拆成多个参数。

**解法**：写 `.mjs` 文件，用 `-e "await import('file:///C:/路径/脚本.mjs')"` 调。路径里的空格写成 `%20`。

### 1.5 中文乱码

用 `Set-Content` 写脚本会乱码，用 UTF-8 编辑器写。

## 二、登录态

### 2.1 登录态失效

**现象**：访问任何页面都跳登录页。

**解法（五步）**：
1. 打开登录页
2. 点账号输入框，触发浏览器自动填充
3. 校验隐藏字段里的账号和密码长度
4. **按 Escape 关下拉**，点最靠下的登录按钮
5. URL 跳回目标页即成功

**坑**：**绝对不要用键盘 type 填账号**，会被自动填充叠加、把账号拼长一位。

## 三、通用前端操作技巧（最有用的一节）

### 3.1 点了没反应 → 点元素本身 / 强制点击

`click(selector)` 报告成功但页面没变化时，某些按钮的点击事件绑在**特定子元素**上，坐标点击会命中但事件不触发。
改为点元素本身，或加 `{ force: true }`。实测在「组建团队」「提建议」这类按钮上有效。

```js
await page.click("text=组建团队", { force: true, timeout: 8000 });
```

### 3.2 选择器匹配到隐藏元素 → 用可见性筛选

**现象**：`fill("textarea.comment-textarea", text)` 报告成功，但页面没内容。

**原因**：同一个 class 有多个元素（PC 版 + 移动版），选到了 `display:none` 的那个。

**解法**：用 placeholder 等唯一属性 + 判断可见。

```js
const ta = Array.from(document.querySelectorAll("textarea"))
  .find(t => t.placeholder?.includes("写下您的评论") && t.getBoundingClientRect().width > 0);
```

### 3.3 填不进值 → 用原生 setter + 派发事件

Vue/React 受控组件对直接赋 `value` 不认，要用原型链上的 setter。

```js
const setter = Object.getOwnPropertyDescriptor(window.HTMLTextAreaElement.prototype, "value").set;
setter.call(ta, text);
ta.dispatchEvent(new Event("input", { bubbles: true }));
ta.dispatchEvent(new Event("change", { bubbles: true }));
```

### 3.4 富文本编辑器（TinyMCE）

博客正文、云声建议正文都是 TinyMCE。

```js
const f = document.querySelector("iframe.tox-edit-area__iframe");
const doc = f.contentDocument;
doc.body.innerHTML = html;
doc.body.dispatchEvent(new Event("input", { bubbles: true }));
```

**多个编辑器时取最后一个**：`Array.from(document.querySelectorAll("iframe.tox-edit-area__iframe")).pop()`。

### 3.5 提交按钮点不动 → 调页面自己的函数

某些发表按钮点了没反应，直接调：

```js
window.submitForm()
```

成功判据：跳 `developer.huaweicloud.com/processcomplete?type=blog`。

### 3.6 表单提交按钮在所有点击方式下都无效 → 表单直接提交

OAuth 授权页这类，click / 坐标点 / 原生 click 全无效。改用：

```js
const form = document.querySelector("form");
// 常需补上 authorize=1，否则返回 400
const inp = document.createElement("input");
inp.type = "hidden"; inp.name = "authorize"; inp.value = "1";
form.appendChild(inp);
form.submit();
```

### 3.7 元素在视口外导致 fill/click 超时

`element is not visible in the viewport`。

**解法**：先 `scrollIntoView({ block: "center" })`，等 2 秒重新取坐标再操作。**每次操作前重新取 rect**——滚动后坐标会变。

### 3.8 页面内容抓不到 → 等渲染完

大量页面是 SPA。常见情况：
- 初次加载只渲染出导航，主体空白
- 需要 reload 或滚动触发懒加载
- 等 9 秒比 5~6 秒稳

### 3.9 读图与 canvas 导出

远程桌面是 canvas 时可直接导出像素（同源、未被污染）：

```js
const c = [...document.querySelectorAll("canvas")].sort((a,b)=>b.width*b.height-a.width*a.height)[0];
const dataUrl = c.toDataURL("image/png");
```

再用 Buffer.from(base64) 写文件（实测 245KB dataURL → 184KB PNG）。

## 四、积分任务

### 4.1 成长中心任务卡状态严重滞后

**现象**：昨天、今天做完的任务，卡片仍显示「去完成」。

**判定**：**以鸿蒙实践中心的状态为准**（它更实时），或者看接口返回的 `reward=success`。成长中心卡片只作参考。
完整判据源分工见 `04-平台机制与判定口径.md`。

### 4.2 每日浏览案例（+10）不计分

**现象**：直接打开案例详情页、停留 42 秒、滚动、置前台，任务卡仍「去完成」。

**解法**：从任务卡的「去完成」按钮进入案例（可能带来源参数才计分）；页面必须在前台，后台不计时。

### 4.3 Star 鸿蒙案例仓（+30）

- 每天必须 Star **不同**项目，不可取消 Star
- 先从**案例详情页**的「本案例 GitCode 仓库」入口进，直接开仓库页不算
- 点前读按钮状态确认未 starred，点 `.repo-action-group--star` 内的按钮
- 只有 `element.click()` 会真的发请求；坐标点击无效

### 4.4 微认证（每周 +200）—— 最大的一仗

**这条路已完全打通。核心解法：绕过实验点墙，走免费激活。**

前提认知：实验点**没有任何免费途径**（云商店最便宜 ￥10 起且不支持退订，成长中心兑换只有代金券）。别去点「开始实验」，那条路是死的。

**正确路线**：
1. 活动页「0元领开发者证书」→ 填「学校/公司」→ 报名
2. 该页列出多个微认证，点名称进详情页 → 右上「**免费激活**」→ 弹窗「激活成功」
3. **关键**：激活后「进入考试」按钮从 disabled 变可点——**考试不再要求先完成实验**
4. 课程页刷完视频 + 课后测验
5. 详情页「进入考试」→ 准备页四步：隐私政策 → 摄像头检测 → **人脸识别（必须真人）** → 参加考试
6. 24 题 / 45 分钟 / 70 分及格 / 错选漏选都不得分 / **切屏 3 次自动交卷**
7. 交卷后显示分数

**铁律**：**绝不重考**。一次激活只有 1 次考试机会。

**证书**：第 1 个自然日后发放。成长中心任务卡的判定要等证书入库，别提前催。

### 4.5 视频刷进度

平台 UI 只给到 2x 倍速，可以调 `video.playbackRate` 加快（真实播放，不是 seek——服务端按真实播放记录进度）。
**seek 无效**。

**节状态判断**：课程大纲每节前面的 `<img class="accordion-icon">` 的 `title` 属性直接写「已完成/进行中/未开始」，比「已学 %」可靠。

**每节下面还有子视频标签**，播完一个不会自动跳下一个，必须自己点。

### 4.6 课后测验

选项是 `label.el-radio` / `label.el-checkbox`。
**必须 `label.click()` 逐个点并验证 `input.checked`**——连点会把同组前一个取消掉。

### 4.7 发布文章（每日 +60）

流程：文章编辑页 → 填标题、摘要 → 正文写进 TinyMCE → **调 `window.submitForm()`** → 跳 `processcomplete?type=blog` 即成功。

**坑**：
- 摘要框常在视口外，要先 `scrollIntoView` 再点
- **不要碰标签框 `.tagator_input`**，不要点 `#submit-btn`
- 篇数在「我的博客」里核对
- 每日任务只认一篇，不要多发

### 4.8 云声建议（+60 被采纳 / +200 被实现）

`bbs.huaweicloud.com/suggestion` →「提建议」：
1. 选类型：点 `li.types-item`，三选一
2. 标题 `#suggestionTitle`，≤64 字
3. 正文 TinyMCE
4. **必须选关联产品标签**——不选会被拦回。点 `.tagator_input` 展开，再点 `.product-item`
5. 勾 `#agreementBox`
6. 点提交 → 成功：「提交成功，华为云将会在 2 个工作日内完成预审」

**坑**：
- 提交失败后**勾选状态会丢**，必须重新勾再提交
- 文本里**不要写尖括号**（`<id>` 这类），命令行会当重定向符号
- 「数据开小差」= 平台间歇故障，别反复重试

### 4.9 参与开发者赛事（+100）

**核心认知：报名不算分，必须「报名 + 提交参赛作品」。**

排除不能报的：高校站限在校学生；产业合作赛要填已入驻社区名称——没有就别编。
能报的会明写「面向全球全领域开发者（高校、企业、个人）」。

**流程**：
1. 赛事列表 → 点「立即报名」**button 元素本身**（`.list-right button`，点外层 div 不触发）
2. 报名表单多数字段账号已预存
3. 报名成功 → 「组建团队」——普通点击只改 URL 不弹窗，要点元素本身
4. 「上传作品」按钮可能完全无反应 → 改为直接给隐藏 input 塞文件：`input.tiny-upload__input`
5. 成功：作品出现在列表里，状态「评分中」

**作品要求**：zip 格式，≤200MB，命名规范「作品名称+队伍名称+版本号+联系方式」，每天最多传 2 次。

## 五、工具链

### 5.1 飞书多维表格（lark-cli）

- Windows 上是 `.cmd`，Python `subprocess` 调 `.ps1` 会 FileNotFound
- 命令是 **`+record-upsert`**（有 `--record-id` 则更新，无则新建），没有 `+record-update` / `+record-create`
- `--json` 是**顶层字段映射** `{"字段名": 值}`，**不要**包 `{"fields":[...]}`；select 字段值必须是数组
- 必须**按字段 type 精确转换**（select→数组，number→数字），别靠值猜
- `+record-list` 返回 `data.fields` + `data.record_id_list` + `data.data`，三者一一对应
- 逐条调用慢 → 缓存字段类型；偶发超时重跑一次即可（幂等）

**坑**：
- PowerShell 直接传 JSON 会把引号弄坏，要写进 JSON 文件或用 stdin 传
- **JSON 内容里不能有尖括号**：`<id>` 会被 cmd 当重定向符号

### 5.2 去重 key 设计（踩过的真坑）

飞书流水表最初用「日期+来源任务+积分」当去重 key，结果**同一天发多篇文章时 key 完全一样，后写的把前面覆盖掉**——悄悄丢了 2 条记录。

**解法**：key 里必须带上能区分的内容，比如备注前 16 字。

```python
def k(r):
    note = (r.get('备注') or '')[:16]
    return f"{r.get('日期','')}|{r.get('来源任务','')}|{r.get('积分','')}|{note}"
```

**教训**：做幂等更新前先想清楚「什么情况下两条记录的所有 key 字段会相同」。

## 六、平台机制备忘

| 现象 | 真相 |
|---|---|
| 积分不实时到账 | 任务积分按周期统一发放，签到是实时 +10 |
| 卡片显示「去完成」但其实做完了 | 状态滞后 15 分钟~1 天，以鸿蒙实践中心为准 |
| 「数据开小差」 | 平台间歇故障，别重试 |
| 实验页「今日免费名额剩余 N」 | 全体用户共享的营销文案，和你的额度无关 |
| 积分明细打不开 | 接口偶发故障，用页面余额代替 |
| 同一账号不同地方名字不一样 | 见「站点结构与入口地图」的标识对照表 |
