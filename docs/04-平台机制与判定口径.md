# 平台机制与判定口径

> **这份是整个项目里最重要的一份。** 这套东西最容易出错的地方不是「怎么点按钮」，
> 是「怎么判断做成了没有」。把判定搞错，会重做任务、重复领、甚至把已经通过的考试重考。

---

## 一、积分到账口径

- **只有签到实时到账**（点完余额立刻 +10）
- 其余全部任务积分「按任务周期统一发放」，页面原话：
  「完成任务获得成长积分，由华为云开发者成长中心按任务周期统一发放」
- 后台批量结算：多项任务会在**同一时间点**一起入账（实测 2026-11-06 17:47 三笔同时结算，17:49 第四笔跟上），做完不会立刻到账
- **余额没变 ≠ 任务没做**；**任务卡「已完成」≠ 积分已到账**。两个都不能单独当判据
- 任务清单接口（匿名）只能拿「有哪些任务」，拿不到个人完成状态（`is_finish` 恒 0），别指望它

接口：`POST devdata.huaweicloud.com/rest/developer/fwdo/rest/developer/servlet/hdcommunitysoservice/v1/growth/mission/query-mission-list-by-condition`，
body `{"page_no":1,"page_size":60}`；周期枚举 `LIMIT` 仅一次 / `DAILY` 每日 / `WEEKLY` 每周 / `MONTHLY` 每月。

## 二、判据源分工（实测，别换）

| 任务 | 可信源 | 不可信 |
|---|---|---|
| 鸿蒙三条（浏览 / Star / 云端实践） | 鸿蒙实践中心 `#practice-tasks` | 成长中心（严重滞后） |
| DevSpace、Agent 仓 Issue / Star | 成长中心卡片 | AI Agent 实践中心页面（按钮永不变化） |
| 发文章 | 我的博客页「发布于 今天」 | 成长中心 |
| 是否到账 | 成长中心积分数字 | 任务卡「已完成」 |

**判断任务成败的顺序**：鸿蒙实践中心 > 成长中心卡片 > 积分余额。

⚠️ **一个反例**：「参与开发者赛事」这条，成长中心显示「去完成」是**对的**——报名不算分，要交参赛作品。
别照搬「成长中心滞后」的结论把它当成假滞后。

## 三、判定延迟表（判「没认」之前先查这里）

**「做了平台没认」有两种，形态相同、动作相反：**

| 实际状态 | 该做什么 |
|---|---|
| 真没认 | 换做法重试 |
| 认了但慢 | **什么都不用做，等** |

| 项目 | 实测延迟 | 证据 |
|---|---|---|
| Star 鸿蒙案例仓（任务卡「前往 Star 案例仓」入口） | **几分钟** | 2026-11-07 实测，点完回任务卡即转「已完成」 |
| Star 鸿蒙案例仓（案例详情页、同一标签页跳转） | **1~4 分钟** | 01:33 star，01:37 任务卡转已完成 |
| Star 鸿蒙案例仓（案例详情页但**新开标签页**） | **不认** | 2026-11-07 实测，star 成功、计数 +1，等 20 分钟仍「前往 Star 案例仓」 |
| Star 鸿蒙案例仓（直开仓库页） | **永远不认** | 01:02 star，等 25 分钟仍「前往 Star 案例仓」 |
| 每日体验 AI DevSpace | **约 5 小时** | 01:22 完成，07:04 才 +30 |
| 每日浏览一个鸿蒙案例 | 约 5 小时 | 前一日做的，次日 06:11 入账 |
| 每日发布文章 | 约 6 小时（含审核） | 00:33 发，06:34 +60 |
| 微认证 | **不确定，看证书审核** | 考过后次日仍在「证书审核中」 |

**真实教训**：曾连续两次把「还没到」判成「没有」——一次是微认证（把「审核中」当成「没发放」），
一次是 DevSpace（把「5 小时后才给分」当成「平台没认」）。

**这不是两个孤立错误，是一个模式：把「时间差」误判成「结果差」。**

**动作**：凡要写下「假完成」「平台没认」，先查上面的延迟上限；
**没超过上限的，一律写「待结算 / 待核实」，不能写「假完成」**。

## 四、两段式：当天做任务 → 次日核验

核验只判「做了的有没有真被认、分有没有真到账」，不做任务。

**核验算法**：昨天判「已完成」的积分加总，与「今日余额 − 昨日余额」对照；
对不上就是未结算或假完成，写清差多少分。

**记录口径**：
- 任务级明细：日期 / 任务 / 积分 / 当日判定 / 判定来源 / 次日核实 / 结论 / 备注，去重键 `日期+任务名`
- 每天一行汇总：日期 / 签到 / 当日新增积分 / 累计积分 / 完成任务 / 备注
- **没判出来一律写「未见判定」，不许写「已完成」**

## 五、两个长得一样的页面（2026-11 踩过）

**差三个字母，语义完全不同，而且两个页面都正常返回、都不报错、都说「没有」：**

| URL | 它列什么 | 「没有」意味着 |
|---|---|---|
| `edu.huaweicloud.com/my/certificate` | **只列已经发放下来的**证书 | 还没到手 |
| `edu.huaweicloud.com/my/certification?type=micro` | **全部认证记录**，含审核中、待考试 | 真的没这回事 |

曾查微认证结果，走进 `/my/certificate` 看到「您还没有获得任何证书」，据此判成「证书至今未发放」。
实际在 `/my/certification?type=micro` 里写着「证书审核中 / 考试状态：已通过 / 成绩：87分」。

**规则：报「没有」的时候必须附完整 URL。** URL 里是 `/certificate` 还是 `/certification`，一眼能看出查的是哪个视图。
不附 URL 的「没有」，等于没说。

**为什么这两种状态不能混——它们导向的动作相反：**

| 看到的状态 | 该做什么 |
|---|---|
| 没发 / 没考过 | 要催、要重考、要提工单 |
| 审核中 | **什么都不用做，等** |

照「没发」去动作，会去重考一门已经 87 分通过的试——而微认证一次激活只有一次考试机会。
**结论相近但动作不同，也算错，不能拿「方向对」糊过去。**

## 六、微认证有期限，别提前消耗

- 账号下可能同时有「已通过」「待考试」多种状态的微认证记录
- **待考试的别提前考**：有有效期，等于一张有期限的牌；等每周任务刷新后确认真需要再考
- 每周换一门，绝不重考同一门
- 看全部记录（含审核中）去 `/my/certification?type=micro`，看已发放证书去 `/my/certificate`

---

## 七、一句话总结

> **判据看来源，延迟查表格，没超过上限就写「待结算」。**
> 余额、任务卡、审核中，这三个都不能单独下结论。
